# Implementation notes

How the Docusaurus site maps to this HTML version, and where the two differ.

## Source → HTML mapping

| Docusaurus source | HTML equivalent |
| --- | --- |
| `src/pages/index.tsx` + `index.module.css` | `index.html` + `css/home.css` |
| `src/pages/about.tsx` | `about/index.html` |
| Blog plugin (`articles/*.md`) — list, post, tag, archive, authors pages | `articles/**/index.html` |
| Docs plugin (`guides/**`) + autogenerated sidebar | `guides/**/index.html` with a static sidebar |
| `@docusaurus/theme-classic` navbar, mobile sidebar, colour-mode toggle | Markup in every page + `js/main.js` |
| `src/components/ShareButton` + `src/theme/BlogPostItem/Header/Authors` | `.share-button` markup + `js/main.js` |
| `@theme/Tabs` (used in the customisation article) | ARIA tabs markup + `js/main.js` |
| Table of contents, TOC highlight, back-to-top button | `.toc` markup + `js/main.js` |
| Infima + `src/css/custom.css` | `css/styles.css` |
| `static/img` | `img/` (same URL paths) |
| RSS/Atom feeds | `articles/rss.xml`, `articles/atom.xml` (copied from the live build) |
| gtag plugin (`G-8BQ8W900ZZ`, anonymised IP) | Loader at the end of `js/main.js` |

## How the content was produced

Article and guide bodies were taken from the live site's rendered HTML rather
than re-rendered from Markdown. This keeps every rendering detail Docusaurus
applied: heading IDs, the `{/* truncate */}` excerpt on the article list, the
`:::tip` admonition and the Tabs block. Docusaurus-specific class names were
replaced with plain equivalents, and hashed image paths were pointed back at
`img/`.

Design values come from `src/css/custom.css`. Values the site inherits from
Infima (container widths, grid, grey scale, Markdown spacing, breadcrumbs,
pagination, tags) were measured from the live site and written out in
`css/styles.css`, so no framework CSS is loaded.

## Verification

- Pixel comparison against mphomagoro.com: home, about, guides, tags, archive
  and 404 match at 1440, 1280, 1024, 768 and 375px (0.00–0.09% differing
  pixels). The mobile menus are within 0.2% and dark mode is within 0.03%.
- Link audit: all 645 internal links, anchors, images and ARIA references
  resolve, with no duplicate IDs.
- Interaction tests: menu open/close (button, Escape, backdrop), focus handling,
  guides panel in the mobile menu, theme cycle and persistence, tabs (click and
  arrow keys), share fallback to clipboard, TOC highlight, sidebar categories,
  back-to-top, mobile TOC and skip link.

## Intentional differences

Each change is small and fixes a problem visible on the live site; it is not a
redesign.

- **"Browse Guides" button in dark mode.** The live site renders its text as
  `#1c1e21` on a near-black background, which is almost invisible. The text now
  uses the heading colour in dark mode. Light mode is unchanged.
- **Mobile menu contrast.** On the live site, the "← Back to main menu" button,
  the theme icon and the sidebar category arrow in the mobile menu inherit dark
  text colours on the black drawer. They are now light enough to read.
- **Theme toggle hover.** The live hover background is a light grey circle
  behind a white icon. It is now a subtle translucent white.
- **Articles page metadata.** The live page title and description are "Blog" /
  "Blog", although the page is linked as "Articles". They are now "Articles" and
  "Articles on AI Engineering, Solution Architecture and Software Engineering."
  (from the site tagline). The page also has a visually hidden `<h1>` so it has a
  heading.
- **Archive heading level.** The year heading is an `<h2>` instead of `<h3>`
  (no skipped level), styled at the same size.
- **Sidebar categories** use `<button>` instead of `<a href="#" role="button">`.
- **Web manifest.** The original `site.webmanifest` points at
  `/android-chrome-*.png`, which don't exist at that path, and has empty names.
  The copy in `img/favicon/` uses the correct paths and the site name.
- **Images.** Article hero images are served as responsive WebP instead of
  1.8–1.9 MB PNGs. JPEG copies are used for social cards.
- **Analytics** loads only on `mphomagoro.com`, so local and preview
  environments are not tracked.
- **Mobile menu focus.** Opening the menu moves focus into it, and closing it
  returns focus to the menu button. The drawer is `inert` while closed.

## Not carried over

- **`/markdown-page`.** This is the Docusaurus starter's example page ("You
  don't need React to write simple standalone pages"). It isn't linked anywhere,
  so it was left out.
- **`static/img/logo.svg`** (the Docusaurus dinosaur) and
  **`static/img/mpho-magoro-logo.png`** are not referenced by the site.
- **Future-post filtering** (`scripts/filter-future-posts.mjs`). Both articles
  are already published, and the static pages have no build step. Add new
  articles when they're due to go live.
- **Client-side routing.** Navigation is full page loads between static files.
- **Search.** The live site has none.

## Keeping in sync with the Docusaurus site

The HTML pages are static copies. When an article or guide changes in
`articles/` or `guides/`, update the matching page here (and the feeds for
articles). See `README.md` for the checklist when adding an article.
